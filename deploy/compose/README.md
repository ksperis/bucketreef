# BucketReef Compose release bundle

This standalone deployment needs Docker with Compose v2, without a Git checkout
or source build. Published releases support Linux AMD64 and ARM64, including
Docker Desktop on macOS.

1. Before extraction, verify `bucketreef-compose.tar.gz.sha256` with
   `sha256sum -c` (or `shasum -a 256 -c` on macOS).
2. Copy `.env.example` to `.env`, then `chmod 600 .env`.
3. Replace the four secret placeholders with **different** values generated by
   `openssl rand -hex 48`. Keep the release's exact `BUCKETREEF_TAG`.
4. Start `docker compose up -d --wait backend frontend`.
5. Run `docker compose exec backend python -m app.scripts.issue_first_admin_bootstrap`
   and follow the one-time URL to create the first administrator and enroll a passkey.

The frontend is at http://localhost:8080. Services bind to loopback by default;
SQLite lives in the `backend-data` Compose volume. `docker compose stop`
preserves the database and secrets. Keep encryption keys with their database.

For automatic evaluation setup, use the QuickStart bundle. For a complete
deployment, configure TLS, origins, secrets, database and trusted proxies using
the [deployment guide](https://docs.bucketreef.ksperis.com/ops/deploy-docker-compose/).
Enable the optional scheduler with `docker compose --profile operations up -d --wait`.
No S3 service or endpoint is created automatically.

For a split deployment, combine the base file with either
`docker-compose.admin.yml` or `docker-compose.user.yml`, use distinct Compose
project names, and point both stacks at the same PostgreSQL database. Only the
admin stack should enable the `operations` profile. See the deployment guide
for the shared origin/WebAuthn requirements and hardening checker commands.

`docker-compose.ceph-admin-high-security.yml` provides a third, Ceph Admin-only
profile. Use a distinct project/env file when you want an isolated PostgreSQL
database and independent JWT/credential key rings; reuse the main values when
only the runtime/network surface should be isolated.

Before upgrading, stop services and back up the complete volume and matching
`.env`; preserve project name `bucketreef`. Verify the target release bundle,
review migration notes, replace only bundle files, and deliberately update
`BUCKETREEF_TAG` in your existing `.env` to match `VERSION`. Never replace
your keys with example secrets. Database migrations can prevent an image
downgrade; restore a verified database backup with its matching keys for rollback.
