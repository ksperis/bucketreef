# Feature Availability

Use this page when something you expect in **Portal** is missing, disabled, or
read-only.

## What controls what you can do

Portal adapts to the project you selected, your project role, and your role on
each Storage Space. Some functions can also be disabled for the whole project
by an administrator.

| What is missing | Check first |
|---|---|
| Portal itself | Confirm that you were added to the expected project. |
| A Storage Space | Confirm the selected project and ask the space owner or a Portal Manager whether you should have access. |
| Create or edit a Storage Space | These actions depend on your Portal role and the current state of the space. |
| Invite or change collaborators | Open the space's **Collaborators** tab. Some project-membership changes may require a Help request. |
| Create an external link | The project must allow external sharing and your role on the space must allow the action. |
| Create credentials for an external tool | External-tool access must be enabled for the project and available for your account. |
| Previous file versions | The underlying storage must keep versions for that space and you must be allowed to read them. |
| Activity or access logs | The available history depends on your Portal role and on what the project has enabled. |

## What to do

1. Confirm the project shown in the Portal header.
2. Open the Storage Space again from **Spaces** so you start from its current
   state and permissions.
3. If an action is disabled, read the message shown next to it before retrying.
4. If access still looks wrong, open [Help requests](../help-requests.md) or
   contact your administrator with the project name, Storage Space, action, and
   exact error text.

Do not try another workspace to work around a missing Portal permission. A
Portal Manager role is part of Portal and does not imply access to the Manager
workspace.
